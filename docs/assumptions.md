# Принятые допущения

Каждое допущение соответствует вопросу из docs/questions.md. До получения
ответа заказчика реализовано именно так. При ответе меняется точечно в
скрипте agent/scripts/rules.py.

## A1 — повторная отправка (Q1)
Повторная отправка = номер заказа из комментария ФУЛ уже присутствует
в Cloud в любой строке, независимо от статуса (в работе / confirm),
поставщика и бренда. Номер ФУЛ для идентификации не используется.

## A2 — дубль внутри пачки (Q2)
При нескольких ФУЛ с одним номером заказа, которого нет в Cloud,
основным считается ФУЛ с самой ранней датой. При равенстве дат —
первый по порядку строк в файле. Остальные попадают в «Повторные
отправки».

## A3 — формат комментария повторной отправки (Q3)
В листе «Повторные отправки» выводим: номер заказа, номер ФУЛ, дату ФУЛ,
поставщика, существующего логиста из Cloud и готовую строку
«Повторная отправка ФУЛа, ДД.ММ.ГГГГ». Саму дописку в Cloud делает
сотрудник вручную.

## A4 — нормализация способа доставки и страны (Q4)
Способ доставки: trim + lower. air → air. sea, truck, direct truck,
railway → не air. Страна: trim + lower. Китай = {китай, china, cn,
hong kong, гонконг, hk}. Остальное — не Китай.

## A5 — пустые/неизвестные способ доставки и страна (Q5)
- способ доставки пуст или не из списка → группа «не определено»,
  логист «не определено», строка в «Требует внимания»;
- способ = air, страна пуста → группа авиа (страна для air не нужна);
- способ ≠ air, страна пуста → группа «не определено», строка в
  «Требует внимания».

## A6 — история с поставщиком (Q6)
Считаем по всем строкам Cloud, где нормализованный поставщик совпадает.
Статус не фильтруем — учитываем и «в работе», и confirm. Период не
ограничиваем.

## A7 — история недоступного логиста (Q7)
История учитывается только по доступным сотрудникам (состояние
«работает», должность из трёх групп). Если предпочтительный логист
в отпуске или уволен — берём следующего по частоте среди доступных.
Если доступных с историей нет — наименее загруженного в группе.

## A8 — загрузка накопительная (Q8)
Загрузка = число заказов «в работе» в Cloud по этому логисту
плюс число уже назначенных в этой пачке. После каждого назначения
счётчик выбранного логиста +1 для следующих строк этой же пачки.

## A9 — тай-брейки (Q9)
Ничьи по частоте и по загрузке разрешаются по возрастанию табельного
номера. Если табельный номер пуст — по возрастанию ФИО.

## A10 — доступность сотрудников (Q10)
Доступен только сотрудник с состоянием «работает» (trim, регистр не
важен). Всё остальное (отпуск, «Уволен», пусто, неизвестное значение) —
недоступен. Должность должна входить в одну из трёх групп (авиа, ВЭД,
мультимодальн). Ассистенты, руководители и прочие исключены.

## A11 — возможные пропуски и граница Cloud (Q11)
Граница = максимум по Cloud из «Дата получения УЛ»; если пусто —
максимум «Дата подтверждения»; если пусто — максимум cut-off.
ФУЛ с датой раньше границы, отсутствующий в Cloud, попадает и в
«Возможные пропуски», и в «Новые строки Cloud» (помечается в журнале
«раньше последней записи Cloud»).

## A12 — формат дат (Q12)
Все даты в формате ДД.ММ.ГГГГ. Пустая дата — пустая ячейка, не
«не определено». Cut-off переносим как есть из ФУЛ. В новых строках:
- Статус = «в работе»;
- Дата получения УЛ = дата ФУЛ;
- Дата подтверждения и Документы получены — пустые;
- где данных нет — «не определено» (кроме дат).

## Дополнительные технические допущения

- T1. Скрипт читает первый лист каждого файла; имя листа не важно.
- T2. Заголовки ищутся по синонимам, порядок колонок не важен.
- T3. Лишние колонки во входных файлах игнорируются.
- T4. Номер заказа в комментарии ФУЛ ищется регуляркой /S\d{7}/i.
- T5. Если номер заказа не найден — заказ «не определено», строка
  в «Требует внимания», в Cloud не попадает.
- T6. Если в группе нет доступных логистов — заказ остаётся без
  логиста, в другую группу не передаётся.
- T7. Один поставщик в пачке — один логист: если в пачке уже назначали
  логиста на этого поставщика и он доступен, новый заказ идёт к нему.
- T8. Модель (GigaChat) не принимает решений о группе/логисте,
  только пересказывает вывод скрипта.
- T9. Сеть и внешние сервисы не используются, только приложенные файлы.
- T10. Зависимости: Python 3, stdlib + openpyxl + xlrd.
