# Алгоритм распределения

Детерминированный скрипт. Вход — три xlsx, выход — один xlsx с 5 листами.
Все колонки ищутся по заголовкам, не по номеру. Пустые/неизвестные значения
не додумываются: пишется «не определено».

## 1. Чтение файлов и поиск колонок по заголовкам

Для каждого файла:
1. Открыть первый лист (имя листа не важно).
2. Прочитать строку заголовков, нормализовать (trim, lower, убрать лишние
   пробелы, ё→е).
3. Найти нужные колонки по списку возможных синонимов заголовка.
4. Если колонка не найдена — поле считается отсутствующим, в результат
   пишется «не определено» и запись попадает в «Требует внимания».

Колонки ФУЛ (1С): Дата, Cutoff date, Номер (номер ФУЛ), Статус,
Комментарий (содержит «Номер: S0001234 от ДД.ММ.ГГГГ»), Способ доставки,
Бизнес единица, Логист, Контрагент, Страна.

Колонки Cloud: Заказ, Поставщик, Бренд, Логист, Статус (в работе / confirm),
Дата подтверждения, cut-off, Дата получения УЛ, Страна отправления,
Способ доставки, Документы получены, Комментарий.

Колонки Сотрудники: Наименование (ФИО), Текущее состояние, Должность, Код
(табельный номер).

## 2. Нормализация

- Способ доставки: trim + lower. air → air; sea, truck, direct truck,
  railway → не air.
- Страна: trim + lower. Китай = {китай, china, cn, hong kong, гонконг, hk}.
  Остальное — не Китай. Пусто — «не определено».
- Поставщик: trim + lower + схлопывание пробелов + удаление знаков
  препинания (.,;:-'"«»()). Так «ООО Ромашка», «ооо ромашка.» и
  «ООО  Ромашка» считаются одним поставщиком.
- ФИО логиста: trim + lower + схлопывание пробелов.
- Состояние сотрудника: trim + lower. Доступен только «работает».
- Должность: trim + lower. Группа по вхождению ключевого слова:
  «авиа» → авиа; «вэд» → ВЭД; «мультимодальн» → мультимодальные.
  Ассистент, руководитель и прочие — не распределяют.

## 3. Классификация ФУЛ

Для каждой строки ФУЛ по порядку:
1. Извлечь номер заказа из «Комментарий» регуляркой:
   /Номер:\s*(S\d{7})/i. Если не найдено — заказ «не определено».
2. Нормализовать поставщика, страну, способ доставки.
3. Проверить, есть ли заказ в Cloud (по номеру заказа, в любой строке,
   в любом статусе). Есть → повторная отправка.
4. Если заказа нет в Cloud, но такой же номер уже встречался выше в этой
   же пачке → дубль внутри пачки. Основным считается ФУЛ с самой ранней
   датой (при равенстве — первый по порядку строк).
5. Иначе — новый ФУЛ.

Итог по строке: одно из {новый, повторная отправка (Cloud),
повторная отправка (пачка), требует внимания}.

## 4. Определение группы

Если способ доставки не определён или не из списка → группа
«не определено», в «Требует внимания».

Иначе:
- air → «специалист по авиаперевозкам»;
- не air и страна = Китай → «специалист по работе с ВЭД документацией»;
- не air и страна ≠ Китай (и страна определена) → «специалист по
  мультимодальным перевозкам»;
- не air и страна не определена → группа «не определено», в «Требует
  внимания».

## 5. Выбор логиста

Вход: группа, поставщик, Cloud, сотрудники, накопительная загрузка пачки.

1. Доступные = состояние «работает» И должность в трёх группах И
   должность соответствует нужной группе. Ассистенты, руководители,
   отпускники, уволенные — исключены.
2. Если доступных в группе нет → логист «не определено», строка в
   «Требует внимания», заказ в другую группу НЕ передаётся.
3. История с поставщиком: считаем по всем строкам Cloud, где
   нормализованный поставщик совпадает. Статус не фильтруем
   (в работе и confirm). Период не ограничиваем. Считаем по ФИО
   доступных логистов.
4. Если у кого-то частота > 0 — берём максимум. Ничьи — по возрастанию
   табельного номера (пустой табельный — по возрастанию ФИО).
5. Если истории нет (новый поставщик) или предпочтительный недоступен —
   берём наименее загруженного в группе.
6. Загрузка = число заказов «в работе» в Cloud по этому логисту
   + число уже назначенных в этой пачке (накопительно).
7. Ничьи по загрузке — по возрастанию табельного номера, затем ФИО.
8. После назначения загрузка выбранного логиста +1 (для следующих
   строк этой же пачки).
9. Один поставщик в пачке — один логист: если в пачке уже назначали
   логиста на этот поставщик и он доступен, новый заказ того же
   поставщика идёт к нему же.

## 6. Возможные пропуски

Граница = максимум по Cloud из «Дата получения УЛ»; если пусто —
максимум «Дата подтверждения»; если пусто — максимум cut-off.

Если ФУЛ с датой раньше границы отсутствует в Cloud — он попадает
в «Возможные пропуски» И в «Новые строки Cloud» (чтобы сотрудник видел
оба факта), в журнале помечается «раньше последней записи Cloud».

## 7. Формирование выходного xlsx

Листы:
1. Новые строки Cloud — 12 колонок в порядке реестра.
2. Повторные отправки — заказ, номер ФУЛ, дата, поставщик, текущий
   логист из Cloud, готовая строка «Повторная отправка ФУЛа, ДД.ММ.ГГГГ».
3. Возможные пропуски — заказ, дата ФУЛ, граница, поставщик.
4. Требует внимания — заказ, номер ФУЛ, причина (нет номера заказа /
   нет страны / нет способа доставки / вся группа недоступна / нет
   должности / иное).
5. Журнал решений — по каждому ФУЛ: номер ФУЛ, заказ, статус (новый /
   повтор / дубль / внимание), группа, логист, основание (какая
   ветка алгоритма сработала).

Значения по умолчанию в новых строках:
- Статус = «в работе»;
- Логист = выбранный или «не определено»;
- Дата получения УЛ = дата ФУЛ;
- Дата подтверждения и Документы получены — пустые;
- Cut-off — как есть из ФУЛ;
- Где данных нет — «не определено» (кроме дат: пустая ячейка).

## 8. Таблица решений по сложным случаям

| Случай | Что делает скрипт | Куда попадает |
|---|---|---|
| Повторная отправка (заказ уже в Cloud) | строку не создаёт | «Повторные отправки» |
| Дубль внутри пачки | создаёт одну строку по самому раннему ФУЛ | «Новые строки Cloud» + «Повторные отправки» |
| Новый поставщик | наименее загруженный в группе | «Новые строки Cloud» + журнал |
| Предпочтительный логист в отпуске | следующий по частоте среди доступных, иначе наименее загруженный | «Новые строки Cloud» + журнал |
| Предпочтительный логист уволен | то же (уволен = недоступен) | то же |
| Все сотрудники группы недоступны | логист «не определено», в другую группу не передаёт | «Требует внимания» |
| Нет номера заказа | заказ «не определено», строку не создаёт | «Требует внимания» |
| Нет страны (не-air) | группа «не определено» | «Требует внимания» |
| Нет способа доставки | группа «не определено», логист «не определено» | «Требует внимания» |
| Дата ФУЛ раньше последней записи Cloud | создаёт строку + пометка | «Новые строки Cloud» + «Возможные пропуски» |
| Поставщик записан по-разному | нормализация, считается одним | журнал: «поставщик нормализован» |
| Ничья по частоте/загрузке | табельный номер по возрастанию | журнал: «тай-брейк по таб. №» |

## 9. Короткий ответ в чат

Шаблон:

    Новых строк: N
    Повторных отправок: M
    Возможных пропусков: K
    Требует внимания: T

Плюс строка: «Файл результата: <путь>».
