# Результаты прогонов и метрики

Инструмент: Python 3.12.3 в WSL Ubuntu-24.04 (Linux).
Модель: GigaChat API не использовался (нет ключа). Запуск — прямой вызов
детерминированного скрипта `agent/scripts/distribute.py`. В GigaCowork
тот же скрипт запускается навыком, модель только пересказывает результат.
Внешние модели в пайплайне не участвуют.

## Набор данных

- `data/ful_1c.xlsx` — 25 ФУЛ (10 колонок, форма 1С).
- `data/cloud_registry.xlsx` — 33 строки (12 колонок, форма Cloud).
- `data/employees_1c.xlsx` — 11 сотрудников (4 колонки, форма 1С).
- `data/etalon.xlsx` — эталон по 25 ФУЛ (6 колонок).
- `data/generator.py` — генератор с фиксированным seed.

Покрытые ловушки: повтор в Cloud, дубль в пачке, новый поставщик,
предпочтительный логист в отпуске, уволенный логист, вся группа
недоступна (ММ), нет номера заказа, нет способа доставки, нет страны
(не-air), дата ФУЛ раньше последней записи Cloud, разное написание
поставщика (пробелы, точки, ё).

|---|---|---|---|---|---|

Воспроизводимость: **3 из 3 прогонов совпали побайтово** (лист
«Журнал решений» идентичен).

## Метрики по эталону

| Метрика | Значение | Порог по ТЗ |
|---|---|---|
| Полное совпадение по ФУЛ | 25/25 = **100%** | ≥ 95% |
| Точность по полю «Заказ» | 25/25 = 100% | — |
| Точность по полю «Статус» | 25/25 = 100% | — |
| Точность по полю «Группа» | 25/25 = 100% | — |
| Выдуманных значений | **0** | 0 |
| Колонок в «Новые строки Cloud» | **12** | 12 |
| Время ответа на пачку | 0.24–0.25 с | < 60 с |

## Как воспроизвести

    python3 data/generator.py
    python3 tests/run_3x.py

Оба скрипта без сети, без внешних сервисов, только stdlib + openpyxl + xlrd.

## Известные ограничения

- Если во входных файлах нет ни одной из нужных колонок — скрипт
  сообщает об этом, но не останавливается; соответствующее поле
  считается отсутствующим.
- Номер заказа ищется регуляркой `S\d{7}` в комментарии ФУЛ.
  Другие форматы номеров не поддерживаются (допущение A-T4).
- Граница «последней записи Cloud» считается по максимальной дате
  получения УЛ, затем по дате подтверждения, затем по cut-off (A11).
