# Правила распределения (справочник)

## Группы

- air -> специалист по авиаперевозкам
- не-air + страна Китай (китай, china, cn, hong kong, гонконг, hk)
  -> специалист по работе с ВЭД документацией
- не-air + страна не Китай -> специалист по мультимодальным перевозкам

Если способ доставки пуст или не из списка {air, sea, truck, direct truck,
railway} -> группа «не определено».

Если способ не-air, а страна пуста -> группа «не определено».

## Доступность

Доступен только сотрудник:
- состояние «работает» (trim, регистр не важен);
- должность содержит одно из: авиа, ВЭД, мультимодальн.

Ассистенты, руководители, отпускники, уволенные — не распределяют.

## Выбор логиста

1. Один поставщик в пачке -> один логист (если он доступен).
2. Иначе — чаще всех работал с этим поставщиком (по всем строкам Cloud,
   статус не фильтруется).
3. Иначе (новый поставщик или предпочтительный недоступен) — наименее
   загруженный в группе: число заказов «в работе» в Cloud + уже
   назначенные в этой пачке.
4. Ничьи — по возрастанию табельного номера, затем ФИО.

## Повторные отправки

- Заказ уже есть в Cloud (в любой строке, в любом статусе) ->
  строка не создаётся, попадает в «Повторные отправки» с комментарием
  «Повторная отправка ФУЛа, [дата]».
- Дубль внутри пачки (один номер заказа дважды, заказа нет в Cloud) ->
  основной ФУЛ с самой ранней датой, остальные в «Повторные отправки».

## «Не определено»

Пишется вместо любых данных, которых нет: номер заказа, страна,
способ доставки, группа, логист. Правдоподобные значения не
подставляются.

## Строки Cloud (12 колонок, порядок обязателен)

1. Заказ
2. Поставщик
3. Бренд
4. Логист
5. Статус
6. Дата подтверждения
7. cut-off
8. Дата получения УЛ
9. Страна отправления
10. Способ доставки
11. Документы получены
12. Комментарий

## Даты

Формат ДД.ММ.ГГГГ. Пустая дата — пустая ячейка (не «не определено»).
